# PVF 职业枚举解析与常量固化（character.lst / .chr）

## 1. 目的与范围

从 `PVF/86JPL/Script.pvf` 一次性提取「基础职业 → 可转职分支 → 一觉/二觉名称」枚举，
固化为 `src/utils/jobGrowNames.js` 常量，供管理前端（`src/components/SendItemView.vue`
修改角色面板等）展示使用。**应用运行时不加载 PVF**，仅消费固化枚举（用户口径：
当前项目只使用解析好枚举的值）。

解析语义对照参考同级 A21 权威 GM 工具的 `PvfIndexService.Jobs.cs`
（`BuildJobNames`：读 `character/character.lst` → 各 `.chr` 的
`[growtype name]` 与 `[growtype N]` 段 `[awakening name]`），本仓提取脚本按同语义独立实现。

## 2. 数据来源与解析语义

### 2.1 character/character.lst

- 整份为一串 ``数字 `相对路径` `` 对，数字即基础职业 id（job），路径相对 `character/` 目录。
- 86JPL 基线共 14 条（job 0-13）。lst 内路径为混合大小写书写（如 `Swordman/Swordman.chr`），
  而**归档文件树 fullpath 一律小写**（如 `character/swordman/swordman.chr`），
  匹配时必须做小写归一，否则全部落空。

### 2.2 .chr 内职业结构

| 结构                            | 语义                                                                     |
| ------------------------------- | ------------------------------------------------------------------------ |
| `[growtype name]` 数据行        | 反引号名单：首项 = 基础职业名；第 k 项（k≥1）= 转职分支 first=k 的转职名 |
| `[growtype N]` 数值段           | 转职分支 first=N-1 的数据段；N=1 为未转职段（无觉醒数据）                |
| 段内首个 `[awakening name]`     | 反引号名单依次为一觉名、二觉名；段内出现重复块时**首块为准**             |
| 名单第二项缺失                  | 该分支不支持二觉（无 `[awakening 2]` 段）——展示层只提供一次觉醒选项      |
| 整段缺失（无 `[growtype N+1]`） | 该分支不可觉醒——展示层锁定未觉醒                                         |

grow_type 线缆编码与网关一致：`(second << 4) | first`
（见 `docs/gateway-update-role.md` §2.3）。

### 2.3 grow_type 八位编码解码规则（含实例走查）

角色携带的 `grow_type`（`RoleInfo.grow_type`，int32）是一个 8 位位编码字节：

```
grow_type = (second << 4) | first
            └─高 4 位─┘  └低 4 位┘
```

| 位域                              | 取值 | 含义                                                                                  |
| --------------------------------- | ---- | ------------------------------------------------------------------------------------- |
| `first = grow_type & 0xF`         | 0-5  | 转职分支：0=未转职；1-4=已实装分支（`JOB_GROWS[job]` 键）；5=未定案占位（枚举未收录） |
| `second = (grow_type >> 4) & 0xF` | 0-2  | 觉醒档位：0=未觉醒；1=一次觉醒（名单第 1 项）；2=二次觉醒（名单第 2 项）              |

名称解析按「先分支、后觉醒」两级查表（实现为 `jobGrowNames.js` 的
`growLabel(job, first, second)`）：

1. 以 `job` 查 `JOB_GROWS` 得分支表；
2. 以 `first` 查分支表得 `{ name, awakens }`——`name` 即转职名，`first=0` 时无此步，直接「未转职」；
3. `second > 0` 时以 `awakens[second - 1]` 取觉醒名，组合为 `` `${name}·${觉醒名}` ``；
   名单对应位缺失则回退泛化文案（`awakens[1]` 缺失 ⇔ 不支持二觉，见 §4.4）。

**完整走查：job7、grow_type=33 → 格斗家(男)·气功师·二次觉醒念皇**

| 步骤       | 运算/查表                              | 结果                 |
| ---------- | -------------------------------------- | -------------------- |
| 位拆分     | `33 & 0xF`                             | `first = 1`          |
|            | `33 >> 4` → `0b10 & 0xF`               | `second = 2`         |
| 基础职业名 | `JOB_NAMES[7]`                         | `格斗家(男)`         |
| 转职名     | `JOB_GROWS[7][1].name`（86JPL 提取值） | `气功师`             |
| 觉醒名单   | `JOB_GROWS[7][1].awakens`              | `["狂虎帝", "念皇"]` |
| 二觉名     | `awakens[2 - 1]`                       | `念皇`               |
| 组合文案   | `growLabel(7, 1, 2)`                   | `气功师·念皇`        |

即 33 的二进制 `0b0010_0001`：高半字节 `0010`＝二次觉醒，低半字节 `0001`＝转职分支 1。
反向构造同理——把角色设为「气功师·二觉」时下发 `grow_first=1`、`grow_second=2`，
线缆 grow_type 编码 `(2 << 4) | 1 = 33`。

展示层等价调用点：SendItemView.vue 的 `growParts()` 做位拆分、`growComboLabel()`
调 `growLabel()` 出文案；未转职角色（first=0）显示「未转职」，与网关
`(second << 4) | first` 的回显约定逐位一致。

## 4. 已知数据特征（非解析错误）

以下均为 86JPL 归档内真实数据特征，按原文登记，不做净化或补全：

1. **字符串表占位键**：守护者 first=3/4（`growtype_name_219`、`growtype_name_222`）、
   魔枪士 first=3/4（`growtype_name_232`、`growtype_name_235`）为客户端本地化引用键。
   86JPL 归档内**不含任何 .str 字符串表文件**（扫描结果 0 个），归档侧无法还原实际名称，
   按原键保留；其分支同时无觉醒数据段（§3 中标「—」），展示层视为不可觉醒。
2. **5 转分支未定案，常量不收录**（用户口径）：各常规职业归档内存在 first=5 分支槽位，
   名称带 `//(后续确认)剑魔 / 邪神 / 金刚力士` 注释式前缀（标记未定案），或复用基础名
   （格斗家/魔法师/神枪手等空置同名槽）；其觉醒数据多为复制邻段的占位（如 job0 first=5
   复制阿修罗名单、job4 first=5 段内仅单块且二觉位为 `狂虎帝`）。这些分支在 86JPL 快照中
   均不可实装使用，`JOB_GROWS` 一律不收录 first=5；协议仍允许 `grow_first=0-5`，
   角色已落在 5 转分支时由展示层追加「当前分支」兜底项或回退泛化文案。
3. **直进职业**：黑暗武士（9）、缔造者（10）全分支同名且不存在任何 `[growtype ≥2]`
   数值段，仅 `[growtype 1]` 段带觉醒名单——提取规则做直进职业回退处理（仅保留
   分支 first=1，觉醒名单取该段）。
4. **二觉支持差异**：86JPL 快照中所有已实现觉醒数据的分支均含一觉+二觉两项；
   「部分职业暂只支持一觉」的场景由**名单长度**承载（第二项缺失 ⇔ 不出二觉选项；
   整段缺失 ⇔ 锁定未觉醒），属版本差异，常量结构与展示逻辑天然兼容。

### 5.2 SendItemView.vue 行为约定（展示层）

1. **卡片默认回显查询结果**：选中角色后，修改角色面板各输入控件一律回显当前值——
   当前值行显示 `JOB_NAMES[job]` + `growComboLabel`（转职名·觉醒名），改名框回显当前名、
   等级框回显当前等级、转职/觉醒下拉回显当前档位；三组启用开关默认关闭仅解锁编辑，
   未启用时也可看到现状。`RoleInfo.job` 为 proto3 int32，网关侧 job=0（鬼剑士男）不序列化、
   前端解码后字段缺失（undefined）——枚举层统一按 0 归一化处理（§5.1），
   仍以真实分支名/觉醒名展示；仅当表中确无该 job / 分支（如未实装 5 转、未知职业）时
   才回退既有泛化文案（「转职分支 N」「一次觉醒」等）。
2. 转职下拉：按角色 job 动态生成（真实分支名），未转职固定为首项「未转职」；
   无枚举表回退泛化选项；角色当前已落在表外分支（协议允许但未收录的 5 转）时
   追加「（当前）」兜底项避免显示裸数字。
3. 觉醒下拉：由所选分支的 `awakens` 名单驱动，标签形如「一次觉醒：剑圣」「二次觉醒：剑神」；
   二觉名缺失则不出现二觉选项（对应「只支持一觉」）；分支无可觉醒数据或未转职时
   锁定「未觉醒」并禁用；切换分支后当前档位超出新名单时钳回一觉。选项列表不受启用
   开关门控；表外分支名单为空而角色实际带档位时以「（当前）」兜底项保证回显。
4. 既有协议校验不变：成对启用、范围 0-5 / 0-2、未转职锁零、觉醒参考等级门槛
   （`AWAKEN_MIN_LEVEL`，见 `docs/gateway-update-role.md` §3）；改名与当前名相同时
   按「未变化」拦截提示。
5. confirm 汇总文案同步使用真实名称替换泛化档位描述。
